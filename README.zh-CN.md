# 榫卯 Tenon

> 把设备、软件与 AI 串成**一条可查的任务链**的自建中枢。

## 只回答三个问题

榫卯服务的是一个人、一个 3–20 人的小工作室，或有内网与合规要求的企业团队：

| 问题 | 你看到什么 |
|---|---|
| **这台机器能做什么？** | 设备卡：提供哪些能力、谁可以用、每条关系都有证据、授权何时到期 |
| **这件事办到哪一步？** | 一条时间线：草案、确认、排队、执行中、完成/失败、已回传，每一步都有证据 |
| **数据出了哪道门？** | 数据域标记 + 可导出的审计：哪台设备、哪个能力、哪个模型、哪条通道 |

相邻品类解决「能不能连」；榫卯解决连上之后的**谁批准、办到哪、数据去了哪**。协议解决连接，账本解决责任。

## 六项能力（v0.1.0 范围）

| # | 能力 | 你会得到 |
|---|---|---|
| 1 | **自动发现** | 节点上线即出现在列表并标出能力；可补扫、可隐身、可只读接入；失败要说明卡在哪一步 |
| 2 | **能力视图** | 谁提供、谁能用、最近三次调用、授权到期；每条关系可点开证据；无证据显示「未知」 |
| 3 | **任务代办** | 手机说一句 → 电脑出现五段草案；不可逆动作逐次确认；可取消、可重试 |
| 4 | **影响预览** | 断开设备/撤销授权前，列出会断的任务，分「确定/可能/未知」；取消后状态零变化 |
| 5 | **消息回传** | 只发摘要+链接，正文不出内网；限流→排队重试→换通道→标未送达，全程可见 |
| 6 | **部署与体检** | 一页看清阻断/警告/提示/无法判定；没有发现时列出检查范围；审计可导出 |

## 设计原则

- **本地优先**：全部跑在你自己的机器或局域网；没有厂商云在中间；公网中继可选、默认关闭。
- **证据优先于猜测**：关系强度只有「确定/可能/未知」；没有证据的关系显示「未知」，绝不把猜的写成事实。
- **追加式账本**：事件带哈希链，启动重放成索引——崩溃恢复、审计、导出、迁移读同一个事实来源。
- **零运行时依赖**：只用 Node.js 内置模块；前端原生 HTML/CSS/JS，无 CDN、无外链字体，拔掉公网功能不减。
- **插件边界**：AI 提供方、能力、回传通道、MCP 风格能力桥都是接口，不是写死的集成；换模型、换通道不动核心。

## 架构（v0.1.0 计划）

```text
[手机网页 /m]   [桌面网页 /]   [CLI]
        \           |            /
               中枢 Hub（Node.js）
   账本 · 索引 · 能力注册表 · 任务引擎 · 影响预览 · 通道 · 体检 · AI 提供方
                  |
              节点 Agent ── 注册能力、拉任务、心跳、回报事件
                  |
   capabilities/*  image.crop · file.hash · llm.summarize · channel.notify · ...
```

## 快速开始（随 v0.1.0 提供）

```bash
git clone https://github.com/minzzj/tenon.git
cd tenon
node server/start.js        # 需要 Node.js >= 22
# 打开 http://127.0.0.1:7410
```

仓库保持诚实：**上面的命令在 v0.1.0 代码落地时才真正可用**。当前这个底座提交只包含仓库、许可证与文档骨架。

## 测试承诺

按用户的方式测：**真实 Chrome、真实点击、真实文件、真实强杀进程**——不是用 API 调用冒充测试。证据（截图、断言、日志）归档在 `docs/测试证据/`；README 里的数字会与 v0.1.0 的真实证据一致。单元测试用 `node --test`。

## 仓库结构

```text
server/        中枢：HTTP API、账本、索引、任务引擎、体检
node-agent/    节点：能力注册、任务执行、心跳
public/        桌面控制台 + 手机遥控页（无 CDN、离线可用）
plugins/       能力 / 通道 / AI 提供方接口
test/          单元测试 + 真实浏览器 E2E 脚本
docs/          使用手册、测试方法、假设清单、测试证据、图片
scripts/       安装 / 启动 / 停止脚本
```

## 非目标

榫卯**不**实现 Matter/Thread 配网，**不**做云端自动化 SaaS，**不**做网盘或聊天，**不**做 GUI 点击机器人。它站在这些东西之上：给你已有的设备、软件和模型加一层「任务与责任」。
