# 榫卯 Tenon v2.1 · 产品愿景：消费级超级终端

> **方向已确认（2026-10-25）。** 榫卯不是企业系统，而是给**家庭、个人与小团队**用的消费级「超级终端」：一个小软件，调动家里所有设备与所有程序。v2-P0 的互联与素材底座已实现并通过隔离实例验收（9/9，2026-10-25 14:11）；v2.1 超级终端 P0 今晚交付中，**未验收前一律标 ⏳**。本文写「我们想做成什么体验」，不把未完成功能写成已完成。

## 1. 一句话愿景

**一个小软件，调动家里所有设备与所有程序。**

你对着手机说一句「把刚才拍的照片甩到电脑上」，电脑屏幕就打开那张照片；你倾斜一下手机，正在看的页面自动滑上大屏；家里的电视、音箱、打印机、NAS 和几台电脑，在同一个首页上像一台设备一样被调用。

**这不是企业系统。** 它面向的是：一个想少装几个软件的个人、一个想全家共享照片的家庭、一个工作室里几个人共用设备的**小团队**。企业版是**可选插件形态**，不是主线（见 §8）。

## 2. 三种典型情况

| 情况 | 谁 | 想要什么 | 在榫卯里怎么体现 |
|---|---|---|---|
| 个人 | 一个人，两三台设备 | 手机和电脑之间别再用聊天软件传来传去 | 互联配对、文件互传、剪贴板、超级终端首页 |
| 家庭 | 一家人，手机/电脑/电视/音箱/打印机/NAS | 全家设备一起用、照片共享、老人小孩也能用 | 家庭成员、家庭相册、语音一句话、手机甩屏上大屏 |
| 小团队 | 3–10 人，工作室/小公司 | 共用电脑和素材，不折腾服务器与权限体系 | 成员与角色基础（不做审批体系）、素材库共享、场景 |

> 设计裁决：任何时候先问「一个普通用户能不能在半分钟内用一句话完成这件事」，而不是「权限模型够不够复杂」。

## 3. 三个核心体验

### 3.1 一句话调动全家设备与程序

- 打开超级终端首页，输入或**按住说话**：「打开电脑上的微信」「把这张照片甩到电脑」「回家模式」「放首歌」。
- AI 理解意图 → 拆成**可读的执行计划**（每步一行：图标 + 人话动作 + 状态 ✅/⏳/❌），而不是黑箱。
- 计划可以跨设备、跨程序：手机说一句，电脑上的程序被打开、照片被显示、文件被打印。
- **不可逆动作必须确认**（发送、删除、打印、关机等）：确认文案写清「将发生什么、影响谁、能否撤销」。
- 语音不可用（无麦克风/浏览器不支持/权限拒绝）时自动降级为文字输入，并明确提示「已切文字」——不假装听懂了。
- AI 不可用（无 key/断网/预算耗尽）时降级为规则引擎，仍能处理常见指令，并标注降级原因。

### 3.2 手机一倾，内容滑上大屏

参考鸿蒙「超级终端」的直觉：**内容跟着人走**。

1. 手机上正在看的页面/照片/文字，点「甩到电脑」或**把手机向前一倾（倾角快速变化 > 25°，防抖 1 秒）**；
2. 手机显示「正在甩到电脑…」；
3. 电脑大屏上对应的接收页以 0.3 秒滑入动画呈现，并高亮提示「从手机流转过来」，可「在电脑上打开 / 收藏」；
4. 反向同理：电脑上的内容也可以流转到手机（P1 增强）。

流转不是投屏镜像，而是**把手头这一份内容交到另一台设备上继续用**——像苹果接力（Handoff）一样自然，但跨 Windows / Android、且留在自己的局域网里。

### 3.3 素材与设备自动连成一张网

- 手机拍的照片、电脑里的文件、NAS 上的旧素材，**自动归集**到同一个素材库；内容哈希去重，同一张图只有一条记录。
- 搜索不用记文件名：OCR 识别出的文字、标签、来源设备、时间都能搜。
- 手机暂存几样东西到**中转站**，电脑上一次取用（反过来也成立）。
- 每一件素材都能看到「从哪来、被谁用过、在哪台设备上」——这就是账本在消费级场景里的价值：不打扰你，但需要时查得到。
- AI 理解增强（语音转写、视觉标签、语义搜索）为 **P1/未实现**；P0 先做 OCR + 文件名/标签/类型/设备/时间搜索。

## 4. 对标：我们跟谁像、哪里不同

| 能力 | 鸿蒙超级终端 | 苹果接力（Handoff） | 小米妙享 | 榫卯 v2.1（目标） |
|---|---|---|---|---|
| 设备发现与组合 | 强（华为生态内） | 弱（同 Apple ID） | 中（小米生态内） | 局域网自动发现 + 配对，跨 Windows / Android |
| 手机→电脑流转 | 强（生态内） | 强（苹果生态内） | 中 | 甩屏 + 按钮 + 接收页，跨系统 |
| 跨设备调程序 | 生态内 | 有限 | 有限 | 一句话让 AI 调不同设备上的不同程序（P0 首发重点） |
| 素材归集与搜索 | 有限 | 有限 | 有限 | 自动归集 + OCR/标签/时间搜索 + 中转站 |
| 可查、可审计 | 弱 | 弱 | 弱 | **每步写入本机事件账本，可追溯、可导出**（v0.1 起的底座） |
| 不可逆动作保护 | 弱 | 弱 | 弱 | **逐次确认**，确认文案写清后果 |
| 本地优先/私有 | 否 | 否 | 否 | **默认零外联，局域网直连，可私有化** |
| 开放性 | 生态封闭 | 生态封闭 | 生态封闭 | Windows / Android 开放，接口可扩展 |

一句话差异：**别人做「连得上」，榫卯做「连得上、看得懂、叫得动、查得到」。**

## 7. 与原始愿景的对照

原始《产品愿景与实现要求》回答的是**责任问题**（谁批准、办到哪、数据去了哪）；用户最新澄清把**体验问题**提到了前面（高度可视化、高度方便、像鸿蒙）。两者不是替代关系，而是同一套底座的不同出口。逐项对照如下：

### 7.1 三个问题的映射

| 原始问题 | 消费级转译 | 保留 / 弱化 / 延伸 |
|---|---|---|
| 这台机器能做什么？ | 「**我的设备与程序能干什么**」——超级终端首页的设备卡片与程序 tiles，一眼看懂 | **保留并强化**：从企业式「能力视图」变成默认首页的一等公民 |
| 这件事办到哪一步？ | 「**我说完这句话后，它办到哪了**」——AI 计划步骤逐行显示 ✅/⏳/❌，失败说清卡在哪 | **保留并强化**：时间线仍是账本事实，只是用消费级语言呈现 |
| 数据出了哪道门？ | 「**我的东西在哪个设备上、有没有出家门**」——素材来源/引用可查，默认不出局域网 | **保留但降为用户可见的轻提示**；审计导出等能力留在高级/可选插件 |

### 7.2 六项能力的映射

| 原始能力 | 消费级形态（v2.1） | 处理 |
|---|---|---|
| 1 自动发现 | 首页自动出现设备与程序；同一 WiFi 免配置 | **保留并强化**（默认体验） |
| 2 能力视图 | 设备卡上的「一句话能力」+ 程序 tiles；点开才看证据/授权细节 | **保留但降层**：证据与授权从主界面收进详情 |
| 3 任务代办 | 一句话 → AI 计划 → 跨设备、跨程序执行；不可逆逐次确认 | **保留并延伸**（多步计划、跨设备程序调度是 v2.1 重点） |
| 4 影响预览 | 断开设备/移除流转前的提示（确定/可能/未知机制保留在后台） | **弱化**：消费级少用「断开」语义；机制留下，界面少打扰 |
| 5 消息回传 | 结果直接回到首页计划状态 + 手机通知；外部通道（微信/邮件）为可选 | **降级为可选**：消费级不需要「回执发微信」才能用 |
| 6 部署与体检 | 一个小软件启动；体检报告收进设置页 | **保留但降层**：普通用户无感，出问题才看 |

### 7.3 三条承诺的映射

| 原始承诺 | 消费级表达 |
|---|---|
| 说得清 | 计划步骤 + 每个动作可展开证据；不用记「它刚才做了什么」 |
| 收得到 | 结果在首页和手机通知里；不强迫装某个聊天软件 |
| 留得住 | 素材、设备、操作记录都在自己家里/自己的电脑上；拔掉公网核心功能不减 |

**保留的硬底线**：事件账本、不可逆逐次确认、本地优先、未知就写未知。**弱化的企业语义**：组织/审批/角色/保留期/数据域——保留实现（可选插件），但不进入消费级主线界面。

## 8. 企业版 = 可选插件形态，不是主线

- 家庭/个人/小团队用户**不需要**企业插件：不出现审批、角色、组织、审计保留期等概念，界面用「家 / 家人 / 我的设备 / 程序」。
- 企业能力（角色、动作权限、审批开关、审计保留期、企业微信/钉钉/SSO 适配器）在 v2-P0 已实现为独立模块，以**可选插件**方式开启；开启后是额外控制台，而不是默认首页。
- 企业版不会影响消费级交付节奏；真实企业集成（凭据对接）属于 P1。

## 9. 不做什么

- 不做企业管理系统 / 审批流产品；不做云端 SaaS、多租户。
- 不做 Matter/Thread 配网；不做投屏协议私有实现军备竞赛（Miracast/AirPlay 私有实现）。
- 不做 iOS 后台控制（iOS 二期只做手动互传）。
- 不做万能远程桌面 / GUI 点击机器人；不代替你在电脑上点点点，只调动程序与设备。
- 不采集与任务无关的个人数据；剪贴板/通知监听需显式授权，可随时关闭。

## 10. 验收口径与证据纪律

- v2.1 P0 的验收要**真实浏览器 + 真实桌面动作 + 真机（有设备时）/模拟器**；证据归档到 `docs/测试证据/` 后才在 [交付物清单](交付物清单.md) 回填 ✅。
- 手机真机未接入时，明确写「模拟器/浏览器手势验证，未真机实测」；模拟设备必须标 `simulated:true`。
- 不写「已测试」除非有证据；不把「今晚交付中」写成「已完成」。
- 回归要求：v0.1 的 146 条单元测试、v0.1 真实浏览器 E2E（9/9）、v2-P0 隔离实例验收（9/9）不得回归。
