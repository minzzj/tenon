# 测试方法

> 原则：**不用 API 调用冒充用户操作。** 能用真实浏览器点的就真实点，能用真实文件/进程验证的就真跑。

## 四层测试

| 层 | 工具 | 验什么 |
|---|---|---|
| 单元测试 | `node --test` | 账本哈希链与重放确定性、幂等键、影响分级、体检规则、通道状态机 |
| 真实浏览器 E2E | 真实 Chrome（真实点击/输入/截图） | 手机→草案→确认→执行→回执、影响预览取消、体检、审计导出、断网演练、重启恢复 |
| 真实进程/文件 | 启动器、真实示例文件、job 强杀 | 图片裁切可肉眼验证；强杀后重启不重复执行、事件不丢 |
| 故障演练 | 强杀、账本截断、只读降级、通道限流、外联关闭 | 显式降级而不是静默失败 |

## 证据口径

- 每次全量测试写出 `docs/测试证据/测试结果-<时间戳>.md` + `.json`：环境、命令、断言数、失败现场、截图路径。
- 截图由真实浏览器自动生成，不用手截；发布前在**中性路径**重跑，避免暴露本机路径。
- 文档里的每个测试数字必须与证据文件一致。

## 手工验收路线（10 分钟）

1. 双击启动器 → 浏览器秒开。
2. 手机页说一句 → 桌面出现五段草案。
3. 点「不可逆任务」→ 未确认不执行；点拒绝 → 审计出现「未填写」。
4. 断开一台被多条任务引用的设备 → 10 秒内三处标「待确认」。
5. 断开前看影响预览 → 点取消 → 状态零变化。
6. 跑一次上线体检 → 导出报告。
7. 断网演练 → 全页面可用、审计连续。
8. 强杀进程 → 重启 → 任务未重复、事件无丢失、缺口有标记。
